# agent-test：智能体自动化测试（采集型）skill

一个可装载的测试技能：对「能以对话方式提问的智能体」（典型：接了数据源的问数智能体）执行**采集型**自动化测试——组织出题 → 逐条提问 → 采集回答与查询语句回写用例表。**不判分**，通过/不通过由人工事后逐条判定。

## 为什么做这个

测试一个问数智能体时，人工提问既难覆盖全部指标、也难保持口径一致；而让 LLM 自动判分，等于用一个不可靠的东西去检验另一个不可靠的东西。本项目选择的路线是：

> **把「出题、执行、采集」自动化，把「判定」留给人。**

用结构化用例表 + 严格的指标覆盖核对，把人工复核压缩到「逐条看一列」的成本。

## 架构：宿主无关 · 三接口 · 主题隔离

skill 本体零案例数据，任何被测对象、任何宿主都不需要改动主流程：

```
SKILL.md（五阶段主流程，纯方法论）
├── references/
│   ├── angles-library.md        # 测试角度库：T1-T5 幻觉 / E 枚举 / P 压力 / C 复杂 / CS 一致性 + 指标全覆盖横切约束
│   ├── case-table-schema.md     # 用例表 11 字段 schema；断点依据 = 状态列
│   ├── adapter-lark-cli.md      # 适配器：Claude Code 宿主 + 飞书通道（lark-cli）+ 适配器规范（其他宿主照此实现）
│   └── pitfalls.md              # 坑速查（22+ 条）
├── templates/subject-config.md  # 主题配置模板
└── examples/subject-example.md  # 填写示例
```

三个能力接口（新宿主照 `适配器规范` 实现即可运行主流程）：

| 接口 | 用途 |
|------|------|
| 提问通道 | 向被测对象发消息并取回完整回复 |
| 用例表 | 建表 / 写用例 / 按行回写状态与回答 |
| 进度持久化 | 每题落盘，支持中断续跑 |

**主题隔离**：被测对象的专属信息（名称、chat_id、角度取舍）只存在于宿主工作区的 `subjects/*.md`，与技能包完全解耦——换被测对象不重传 skill。

## 五阶段流程

```
Phase 0 环境自检（认证/定位/通路往返实测）
  ↓
Phase 1 探查（问出全部指标/维度，用户确认后才可出题）
  ↓
Phase 2 定角度（角度库 × 主题配置求交集）
  ↓
Phase 3 委托出题与落表 ── 确认门①（规模/时长/覆盖明细）
  ↓
Phase 4 逐条执行（先 smoke 3 条 → 确认门② → 全量；逐题回写+进度落盘）
  ↓
Phase 5 汇总交付（统计 + 人工判定入口 + 新坑沉淀）
```

七条铁律（全文见 SKILL.md）：不判分 / 阶段确认不埋头连跑 / 采信原文 / 探查先行 / 进度落盘 / 主题隔离 / **出题可委托、判分基准不委托**。

## 两个值得展开的设计

**指标全覆盖（横切约束）**：不设「数据准确性」独立板块，而是要求全部用例**合计**让探查到的每个指标至少出现在 1 条「预期返回真实数值」的用例中。计数口径严格：幻觉题/拒答题/仅同源提及不算覆盖；先归一别名与衍生指标再计数；补题后复核对直至全部强覆盖或用户显式豁免。确认门①必须主动交覆盖明细（强/弱/无三档）。

**被测对象自生成用例**：出题委托发给被测对象自己生成——只有它知道背后数据库里有什么字段可用。但「说明/预期」列由测试方按角度库**独立写定**，被测对象自报的预期仅记录备查、不作判分基准（铁律 7）。

## 使用

1. 把本 repo 作为 skill 装载到 Claude Code（整体放入 skills 目录）
2. 复制 `templates/subject-config.md` 到宿主工作区 `subjects/`，按 `examples/subject-example.md` 填写
3. 对测试智能体说「测试智能体」即可触发五阶段流程

> 仓库说明：本 repo 为方法论与框架本体；项目工作区中的主题配置、探查结果、执行进度属于具体被测对象的数据，刻意不入库。
