# 测试用例表：字段 schema 与读写规则

## 逻辑字段（与物理实现无关）

| 字段 | 类型 | 写入方 | 说明 |
|------|------|--------|------|
| 编号 | text | 测试智能体 | `<大类码>-<序号>`：T=幻觉、E=枚举、P=压力、C=复杂、CS=一致性、R=拒答、D=口径（如 T1-2、E3-1） |
| 测试角度 | 单选 | 测试智能体 | 幻觉 / 枚举 / 压力 / 复杂查询 / 一致性 / 拒答 / 口径理解 |
| 涉及指标 | text | 测试智能体 | 本题涉及的指标名（凡涉及指标查询的题必填，可多个逗号分隔）；出题后按此列核对指标全覆盖 |
| 问题 | text | 测试智能体 | 自然语言问句原文 |
| 说明/预期 | text | 测试智能体 | 本题测什么 + 预期正确行为（角度库各细类的「预期」照抄并实例化） |
| 状态 | 单选 | 测试智能体 | 待执行 / 已执行 / 超时 / 发送失败 |
| 回答 | text | 测试智能体 | 被测对象回复原文（超长可截断，尾注`【已截断，全文见进度文件】`） |
| 查询语句 | text | 测试智能体 | 从回复中提取的查询语句（MDX/DAX/SQL 等）；回复未含则留空 |
| 执行时间 | datetime | 测试智能体 | 发出问题的时间 |
| 人工判定 | 单选 | **人工** | 待检 / 通过 / 不通过（初始全为 待检） |
| 备注 | text | **人工** | 失败归因等（初始留空） |

约束：
- 状态、回答、查询语句、执行时间四列**只由测试智能体在执行阶段写入**；人工只动「人工判定」「备注」
- 断点续跑依据 = 「状态」列；凡状态 ≠ 待执行 的行跳过

## 默认物理实现：飞书多维表格（bitable）

建表字段 JSON（type 取 bitable 字段类型，select 用 `options` 列举）：

```json
[
  {"type":"text","name":"编号"},
  {"type":"single_select" 或按 CLI 实际类型,"name":"测试角度","property":{"options":[{"name":"幻觉"},{"name":"枚举"},{"name":"压力"},{"name":"复杂查询"},{"name":"一致性"},{"name":"拒答"},{"name":"口径理解"}]}},
  {"type":"text","name":"涉及指标"},
  {"type":"text","name":"问题"},
  {"type":"text","name":"说明/预期"},
  {"type":"single_select","name":"状态","property":{"options":[{"name":"待执行"},{"name":"已执行"},{"name":"超时"},{"name":"发送失败"}]}},
  {"type":"text","name":"回答"},
  {"type":"text","name":"查询语句"},
  {"type":"datetime","name":"执行时间"},
  {"type":"single_select","name":"人工判定","property":{"options":[{"name":"待检"},{"name":"通过"},{"name":"不通过"}]}},
  {"type":"text","name":"备注"}
]
```

> 字段 JSON 的准确结构以宿主适配器所用工具的官方字段规范为唯一依据（如 Claude Code 宿主 → lark-base 技能 `references/lark-base-field-json.md`），上表只定义字段集与选项值。

读写规则：
- 建表时初始表名按主题配置（一般含被测对象名 + 日期）
- 写入用例：批量 ≤200 条/批，**串行**提交，批间稍歇（并发写同表会被限流）
- 回写结果：按记录 ID 单行更新（执行阶段逐题更新，不做整批重写）
- 记录 ID 在写入用例时保存到进度文件，回写时直接引用，避免依赖行号
