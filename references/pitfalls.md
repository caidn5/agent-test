# 踩坑手册（执行前必读，复盘时追加）

来源：OlapTest 项目 14 条实战经验（Playwright 网页版改写到对话通道语境）+ 后续运行沉淀。**每条坑都注明「症状 → 根因 → 对策」。**

## 完成判定类

1. **把中间态当完成**：流式/分段输出时内容持续变长，单次采样就判完成必截断回答 → 对策：长度连续 3 次轮询稳定 + 最后一条来自被测对象才判完成
2. **把自己发的消息当回复**：水位线不做，读到历史消息以为是回答 → 对策：发送前记录水位线 message_id，只看其后的消息
3. **把上一题的回答当本题的**：上一题超时后立即发下一题，水位线后先到的还是旧回答 → 对策：超时题的处理结束后才发下一题；回复若与问题明显无关，在回答列标注
4. **确认反问打断流程**：被测对象中途反问（确认模型/要补充信息），整批卡死 → 对策：识别反问类型，能答的按主题配置答复后继续等；不能答的如实记录留给人工，不无限等待

## 出题类

5. **用内部命名直构陷阱题**：问题里直接写 `查询 D55="EMS" 的 F05`，被测对象看不懂或行为失真，测的是「翻译能力」不是「用户行为」→ 对策：一律自然业务语言；内部命名只用于说明列
6. **时间幻觉题撞上真空数据期**：测试库数据期间不完整，大量题的真实答案都是「暂无数据」，角度失效 → 对策：Phase 1 探查时问清数据实际时间范围，出题避开或注明
7. **无区分度维度当排名题**：某些维度按设计是统一汇总值（全成员同值），排名题预期写错 → 对策：探查时问清指标×维度关系；此类维度归入 T2 幻觉题而非排名正确性
8. **一致性题在同一会话连续问**：上下文污染，重问会"记得"刚才答过 → 对策：CS 类多轮问法之间尽量隔离（通道不支持新会话时，在题间穿插其他题或注明污染风险）
20. **探查回复是表格当纯文本读**：被测对象回一张多维表格作为元数据汇总，消息文本里只有链接/卡片，不读表就以为它没答全 → 对策：识别回复中的多维表格链接，按适配器分页读全；无权限请用户开通或要文本清单；提取结果注明来源
21. **覆盖率虚高**：核对只数「涉及指标」出现次数，幻觉题（如伪前提"为什么X的指标最高"）、同源关联（如 单价 与 金额/销量 同源）被误计为覆盖，用户追问才发现一批指标无独立题 → 对策：严格口径——该指标是本题「预期返回真实数值的查询对象」才算；先归一别名/衍生再数；核对闭环补题至强覆盖；确认门① 主动交覆盖明细（2026-10-22 实跑教训）

## 自生成类（被测对象出题，2026-10-21 新增）

17. **自生成避重就轻**：被测对象给自己出题时全挑容易的（简单总量、字段直查），难度与覆盖失真 → 对策：委托里写明角度条数与难度分布硬要求；审核发现全简单题要求重出；指标覆盖缺口测试方直接补题
18. **自报预期当判分基准**：被测对象出题时自述的「预期正确行为」本身可能有错 → 对策：说明/预期列由测试方按角度库独立写定，自报预期只记录备查（铁律 7）
19. **生成与执行同会话污染**：被测对象执行时认出「这是我自己出的题」，行为从正常作答变成识别陷阱 → 对策：能开新会话则隔离；不能则在回答列注明污染风险，人工判定时知悉

## 执行与数据类

9. **题间不留间隔**：连续发送把问题灌进还在处理的会话，回答错乱 → 对策：确认上一题完成（或超时）后才发下一题，题间停 5-10s
10. **批量写表并发**：多维表格并发写同表触发限流/冲突 → 对策：串行、≤200 条/批、批间稍歇
11. **整批最后才存盘**：进程中途被杀，全部进度丢失 → 对策：每题回写后立即落进度文件（双写：表 + 本地 JSON）
12. **超长回答撑爆单元格/上下文**：极端题回答超长 → 对策：回答列截断（如 5000 字）+ 尾注，全文存本地进度文件
13. **连续超时不刹车**：被测服务已挂，整批全超时浪费数小时 → 对策：连续 3 题超时暂停整批报告用户

## 通用性类（skill 自身）

14. **表结构变了脚本错位**：按列号/行号硬编码读写，人工调整表格后全错 → 对策：一切读写按字段名与 record_id，禁用位置索引
15. **案例信息泄进 skill**：为图方便把被测对象专属信息写进 skill 文件 → 对策：复盘时审读全部 skill 文件；专属信息只允许出现在工作区主题配置与探查结果中
16. **路径硬编码旧目录**：拷贝工作区后脚本仍指向原位置 → 对策：一律相对当前工作区取路径；进度文件里的绝对路径在续跑时重定向
